# META — исправление связи заданий и безопасного сохранения

Ошибка относится к META College, что подтвердил пользователь.
Регрессионный сценарий: предмет «Мобильная разработка», тема «Навигация страниц»,
курс 1, группа ППО, русский язык, комбинированный урок.

## Первопричина и границы вывода

Сообщение выдавалось в `services/lesson_validation.py`, функции
`normalize_meta_lesson`. Проверка искала всю строку `task_name.casefold()` внутри
`stage['content'].casefold()`. Поле `stage_key` определяло допустимый этап,
но задания не имели устойчивых идентификаторов. Одинаковая деятельность с
разными окончаниями, формулировками или записью `Activity/Screen` / `Activity / Screen`
не проходила такую проверку. Одно сообщение объединяло отсутствие задания и
дублирование, поэтому по нему нельзя было определить ветку отказа.

Дефект воспроизведён без API: указанное пользователем задание не является
буквальной подстрокой следующей реально описанной деятельности:

> Преподаватель проводит опрос: студенты отвечают на вопросы о структуре мобильного приложения и жизненном цикле Activity / Screen.

Прежняя проверка отвергала этот случай, новая проходит. Исходный JSON именно
неудачного AI-запроса не предоставлен, поэтому нельзя доказать, что в том
конкретном ответе причиной было исключительно несовпадение формулировок,
а не реальное дублирование или отсутствующее задание. Подтверждённая
первопричина в коде — хрупкая связь по полной строке вместо ссылки на задание.

Проверка была и остаётся META-специфичной: `create_lesson` вызывает её только
для META; экспорт — для META или META-шаблона. ETEC, ALT, Q и ATKK её не вызывали.
Добавлены тесты генерации, экспорта и сохранения для всех четырёх колледжей.

## Исправление

В существующую структуру каждого этапа добавлен массив `tasks`:

```json
{
  "field_key": "actualization",
  "content": "Описание работы преподавателя и студентов",
  "tasks": [
    {
      "id": "mobile_recall",
      "name": "Опрос по мобильному приложению",
      "instruction": "Ответить на вопросы о структуре приложения и жизненном цикле Activity/Screen"
    }
  ]
}
```

Строка оценивания ссылается на `task_id`. Идентификатор должен существовать
среди заданий этапов. Название и этап для таблицы берутся из этого реестра,
а не из потенциально несовпадающей подписи оценивания. Один ID оценивается
один раз. Неизвестные ID и дублирующиеся задания отклоняются.

Инструкция каждого объявленного задания должна присутствовать в тексте Word.
Если её ещё нет в описании этапа, генератор добавляет именно объявленную
инструкцию. Если деятельность уже описана, текст не дублируется только ради
буквального совпадения названия. Задания из одних лишь строк оценивания
без подтверждения в этапах не создаются.

Для старых ответов без ID выполняется локальное ограниченное исправление:

- нормализация регистра, Unicode, пробелов и разделителей;
- осторожное сопоставление перефразированной деятельности: одинаковый тип
  действия, минимум три предметных термина и совпадение не менее 85% таких
  терминов в конкретном фрагменте этапа;
- при ошибочном `stage_key` — не более двух проходов, сначала указанный этап,
  затем все этапы; результат должен быть единственным;
- присвоение стабильного ID только подтверждённой существующей деятельности;
- исправление однозначных JSON-вариантов: одиночный объект вместо массива,
  словарь заданий по ID, алиасы `task_id`/`task_name`.

Неоднозначность, другая деятельность и отсутствующее задание дают разные
диагностические сообщения. Проверки критериев/дескрипторов, 70 минут,
100 баллов и согласованности баллов дескрипторов сохранены.
Нормализация повторяемая: уже исправленный план не меняется при экспорте.
Дополнительные AI-запросы, автоматические повторные генерации и циклы не добавлены.

## Лимит и сохранение

В репозитории не найден отдельный код списания XP. Учёт попыток представлен
дневной квотой через `generation_events` и RPC `create_lesson_with_daily_limit`.
Исходная ошибка AI-валидации возникала до этого RPC и не должна была расходовать
квоту. Однако был отдельный риск: материал сохранялся до сборки DOCX.

Теперь порядок такой: AI → нормализация → сборка DOCX → атомарное сохранение.
При ошибке валидации или экспорта никакой вызов сохранения/квоты не выполняется.
В JSON сохраняются именно нормализованные ID, время, дата и баллы, соответствующие Word.

Для атомарного сохранения подготовлена **004_atomic_lesson_plan.sql**.
Новая RPC `save_lesson_plan_with_daily_limit` в одной PostgreSQL-транзакции
использует прежний механизм создания/квоты и сохраняет готовый материал.
Если вставка материала завершается ошибкой, создание и событие квоты также
откатываются. При обновлении выбранного существующего занятия проверяется
владелец, новое событие квоты не создаётся. Удаление существующих занятий
или клиентская компенсация через небезопасное удаление не используются.

**Миграция не применена к production. Перед деплоем обновлённого пути сохранения
её нужно проверить и применить отдельно. Без RPC приложение выдаёт понятную
ошибку и не возвращается к старой неатомарной последовательности.**

SQL проверен по существующей схеме репозитория, но не выполнялся на реальном
PostgreSQL: локальная серверная среда PostgreSQL отсутствует. API сохранения
проверен с mocks. Изменений production, XP-правил, размера квоты и деплоя нет.

## Тесты

77 автоматических Python-тестов прошли, без платных запросов. Добавлены 16
регрессионных сценариев/тестов связи заданий и сохранения. Проверены:

- конкретная длинная формулировка из ошибки и перефразированный этап;
- разные подписи при одном устойчивом ID;
- восстановление отсутствующей подписи и ошибочного этапа по ID;
- варианты JSON-структуры без повторного запроса;
- отказ при неизвестном ID, постороннем задании, другом действии,
  неоднозначности и дублировании;
- идемпотентность нормализации и содержимое полученного DOCX;
- 70 минут, 100 баллов и соответствие сохранённого JSON документу;
- единственный mocked-вызов AI;
- изоляция META-проверки от ETEC, ALT, Q и ATKK;
- отсутствие вызовов БД/квоты при ошибке валидации или DOCX;
- один атомарный RPC, обновление существующего занятия и отсутствие
  неатомарного fallback при ошибке сохранения.

```bash
PYTHONPYCACHEPREFIX=/private/tmp/lessonai-pycache .venv/bin/python -m unittest discover -s tests -q
```
