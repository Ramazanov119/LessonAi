# META: единая модель, расчёт баллов и диагностика ответа

13 октября 2026. Актуальное поведение расчёта баллов заменяет правило «не масштабировать явные баллы» из STRUCTURAL_VALIDATION_FIX.md по новому заданию пользователя.

## Установленная причина

В прежней `_normalize_meta_lesson` баллы заданий принимались только как целые числа, но никогда не приводились к 100. Они оставались исходными на всём пути обработки; после проверки каждой строки `sum(item['points']) != 100` завершало генерацию ошибкой. Промпт требовал точной арифметики от AI, а приложение не имело отдельного механизма расчёта. Повторный вызов нормализации при предпросмотре и DOCX создавал несколько мест обработки одной схемы, хотя конкретная прежняя проверка сама баллы не изменяла.

Это установленный механизм отказа, а не подтверждение конкретной ошибки арифметики в последнем ответе API. Фактические числа последней ручной генерации пока неизвестны: её исходный JSON не найден. Не утверждаем, что AI действительно вернул именно 95 или другую конкретную сумму.

Поиск локальных JSON/JSONL/логов и просмотр мест записи в app/config/services показали:

- `docs/qa/meta/lesson_meta_{ru,kk}.json` и `lesson_meta_localized_{ru,kk}.json` — офлайн-образцы из `tests/generate_meta_samples.py`, все с пятью оцениваниями по 20, без task_id;
- `tests/fixtures/meta_ios_{ru,kk}.json` и `meta_rejected_unknown_task.json` — синтетические тестовые примеры предыдущей работы;
- `/private/tmp/lessonai-meta-diagnostics` и `docs/qa/meta/debug` на момент поиска отсутствовали;
- предыдущая диагностика включалась только вручную и сохраняла только структурный снимок при отказе. Исходный API-ответ и результат успешной нормализации не сохранялись;
- production-БД и внешние журналы не запрашивались.

Добавлен `tests/fixtures/meta_ios_95_ru.json`: согласованный по теме, сохранённый пример структуры ответа с суммой 95. Он явно помечен как синтетический, не выдаётся за реальный ответ OpenAI.

## Распределение ответственности и конвейер

`create_lesson` просит AI сформировать содержание, задания этапов, уникальные ID, критерии, наблюдаемые действия/результаты дескрипторов, уровни Блума и относительные веса. Точную арифметику выполняет Python. Схема задания не генерируется из строки оценивания.

Путь META: один вызов провайдера → локальный обезличенный снимок входной структуры, если включён → parsing → структурная нормализация → нормализация длительности/баллов → финальная проверка → локальный снимок канонической модели → DOCX в памяти → атомарный RPC сохранения. Предпросмотр использует тот же канонический JSON, возвращённый генерацией. Рекурсивных исправлений и повторных платных запросов нет.

## Как рассчитываются баллы

`services/meta_scores.py`:

- `weight`: принимает только конечные положительные числа int/float, исключает bool, строки, null, отрицательные/нулевые значения, NaN/Infinity и не представимые как конечные числа значения. Отсутствующее поле отличается от некорректного поля.
- `allocate_scores`: использует точные рациональные веса (`Fraction`), пропорциональные квоты с нижними/верхними границами и метод наибольших остатков. При одинаковом остатке приоритет исходному порядку. По умолчанию задание получает минимум 1; дополнительно поддерживаются целочисленные points_min/points_max. Невыполнимые границы дают `impossible_score_allocation`.
- `normalize_assessment_points`: явные веса сохраняют относительную значимость. При отсутствии весов использует конфигурацию по явному уровню Блума: Remember/Understand/Apply/Analyze/Evaluate/Create → 1/2/3/4/4/5, с соответствующими RU/KK названиями. При частично пропущенных весах конфигурация переводится в единицы имеющихся весов через отношение суммы предложенных весов к сумме соответствующих конфигурационных весов. Анализ слов задания не используется.
- Баллы дескрипторов распределяются внутри рассчитанного балла задания по их собственным относительным весам. Если веса дескрипторов отсутствуют, используется равный вес внутри критерия; при частичном отсутствии — средний из заданных весов. Два явно представленных противоречащих списка весов отклоняются. Новые задания/дескрипторы не создаются.

Примеры результата:

| Входные веса | Итоговые баллы |
|---|---|
| 20, 20, 20, 20, 10 | 23, 22, 22, 22, 11 |
| 10, 20, 30, 40 | 10, 20, 30, 40 |
| 15, 15, 15, 15 | 25, 25, 25, 25 |
| 20, 20, 20, 20, 15 | 21, 21, 21, 21, 16 |
| 0.5, 1.5, 2, 3, 3 | 5, 15, 20, 30, 30 |

Уже корректные целые баллы с суммой 100 и удовлетворяющие границам остаются неизменными. Финальная проверка никогда не перераспределяет баллы.

## Каноническая модель

Модель — JSON-объект с `meta_schema_version=1`, `meta_attempt_id`, `lesson_duration=70`, массивом lesson_stages с duration_minutes/tasks и assessment_items с task_id/stage_key/assessment_criterion/descriptors/descriptor_details/descriptor_points/points.

`descriptor_details` хранит task_id, text, action и result/ requires_result при наличии. Строковые descriptors и evaluation_criteria — совместимые представления для текущего шаблона, формируются из канонической структуры и проверяются на согласованность. Строковые поля этапов синхронизированы с lesson_stages. task_name таблицы берётся из исходного задания этапа.

`declared_tasks` может присвоить детерминированный свободный ID существующему заданию без ID. Это не создание задания. Оценивание без ссылки восстанавливается только при единственном объявленном задании явно указанного этапа; неоднозначность и неизвестная явная ссылка отклоняются.

`validate_meta_lesson` проверяет модель без мутации: этапы и реальные задания, ID/этапы/дубли, критерии, структурные действия дескрипторов, согласованность текстовых представлений, суммы 100 и 70. Обнаруживает также объявленное задание, инструкция которого не включена в каноническое содержание этапа. Совпадение слов задания и дескриптора не требуется. Семантическую педагогическую корректность произвольного текста Python не доказывает; требования к наблюдаемому действию/измеримому результату заданы в промпте и в структуре дескриптора.

Повторный `normalize_meta_lesson` на канонической модели выполняет проверку и подстановку авторитетной даты, не пересчитывает баллы. `build_doc` и `_meta_lesson_body` для канонического объекта вызывают только финальный валидатор. Для прежнего ненормализованного формата сохранена входная нормализация. Существующий META-шаблон, пять столбцов, Times New Roman, локализация RU/KK и оформление таблиц сохранены.

## Получение реального ответа локально

Нужна одна ручная генерация по сообщённым условиям. Запустить локальный интерфейс из корня проекта с явными временными флагами:

```sh
LESSONAI_ENV=development \
LESSONAI_META_CAPTURE_RESPONSES=1 \
LESSONAI_META_DIAGNOSTICS=1 \
LESSONAI_META_DIAGNOSTIC_DIR="$PWD/docs/qa/meta/debug" \
.venv/bin/streamlit run app.py
```

В интерфейсе выбрать META → Мобильная разработка → Операционная система iOS → Новый урок → русский, выполнить одну генерацию. Снимки пишутся автоматически:

- `meta-response-<attempt>-ai_raw.json` — структура до нормализации, с исходными числовыми весами;
- `meta-response-<attempt>-normalized.json` — нормализованная модель;
- при отказе вместо результата — `meta-response-<attempt>-normalization_failed.json` с кодом ошибки;
- при включённой диагностике отказов — отдельный meta-failure JSON с этапом normalization/docx/save.

Снимки содержат summary: actual_points_total, points_by_task, stage_count, task_count, assessment_count и связанные обезличенные ID. Свободные тексты целиком заменяются, метаданные/ключи/токены не включаются, исходные ID заменяются стабильными для снимка task_001 и т. п. Это сохранение исходной **структуры**, а не незащищённого полного ответа: арифметику и ссылки можно воспроизвести, семантический анализ текстов ограничен обезличиванием.

Файлы 0600, каталог при создании 0700. Максимум 20 попыток; повторная запись существующего снимка не выполняется. Ошибка диагностики не маскирует генерацию. Production не разрешает режим даже при включённом флаге. Выключение: перезапустить приложение без временных флагов. Платная генерация автоматически не запускалась.
